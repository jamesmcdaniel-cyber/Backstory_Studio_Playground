Artifact templates with isolated personal copilots — 2026-10-01

Behavior
- Existing public links remain view-only unless an editor explicitly enables
  “Offer as a template with AI Copilot” in Share.
- Signed-in recipients use the public link to create/open one personal copy
  per source, workspace and user. A unique constraint makes concurrent requests
  idempotent, with the agent and initial version in the same transaction.
- Only published source is exported, including data already embedded in it.
  Chat, history, private app state, ROI facts, credentials, integrations and
  source-agent/flow configuration are not copied.
- Each copy has its own private copilot, versions and app state. Its owner can
  edit content and restore versions; other users cannot read or edit it.
- Copilots have bound artifact editing plus inline Python/JavaScript computation.
  They do not discover workspace integrations or repository documents, delegate,
  run flows, or save variants elsewhere. Generic execution and forged artifact
  targets are rejected. The platform model is fixed server-side.
- Configuration controls are hidden, service APIs reject mutations, and database
  triggers protect the artifact binding/sharing and copilot runtime definition.
  The configuration lock survives chat responses and version restores.
- Revocation stops new copies. Existing independent copies remain available.
