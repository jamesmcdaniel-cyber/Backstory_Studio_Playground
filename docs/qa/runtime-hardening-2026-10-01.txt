Runtime, loading and cache hardening — 2026-10-01

STATUS: Implementation deployed, but NOT all P1/P2 findings are closed.
The isolated validator's sustained-load capacity remains a P1 infrastructure blocker.

Implemented
- Session cache resets abort/invalidate pending requests and clear mounted consumers.
  Snapshot consumers also reject responses from a previous session.
- Artifact refreshes are coalesced, bounded by a timeout, and cancelled on teardown
  or local mutation. Failed background refreshes retain the visible artifact.
- Private-state failures retain drafts. Retry reconciles the remote revision,
  recognizes a committed save whose response was lost (independent of JSON key
  ordering), and refuses to overwrite conflicting data. Reload/export are available.
- Artifact polling uses an unchanged metadata check. History is paginated in
  batches of 20; embedded previews now check for newer versions too.
- Unsaved drafts defer frame replacement; the parent warns before unloading.
- Python assets use versioned paths with immutable caching. Legacy URLs revalidate.
  Startup/package loading is separate from execution deadlines. Progress messages
  are protocol-negotiated so old, already-open clients remain compatible.
- Isolated browser validation now has bounded FIFO admission, bounded backoff,
  explicit interaction assertions, and synthetic saved-state/reload checks.
  New interactive versions require a declared primary-workflow test.
  Browser cleanup covers failure paths and all processes of the job-specific UID.
- Unauthorized proposal polling stops instead of repeatedly generating 403s.
